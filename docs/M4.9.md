# M4.9 — the sidecar follows the project, and a node selects its layer

**Status: IMPLEMENTED AND COVERED OFFLINE; LIVE AE ACCEPTANCE STILL OWED**

Two things reported after M4.8. They are unrelated to each other, and both are
the same kind of gap: something the panel learned once at startup, or never told
After Effects at all.

`npm test`: 186 passing. `npm run preflight`: six JSX targets clean. Panel
builds; the host bundle is now four files.

---

## 1 · A Save As left the graph behind

**Reported as:** if on close the user saves the aep into another path, the ntl
file doesn't travel with it.

The graph is stored in a sidecar named after the project file:
`<project>.aep.comp-<id>.ntl`. That path was read exactly once, in
`inspectComp`, from `NTL_ProjectIdentity()`. `Save As` changes
`app.project.file` and nothing else the reconciler cares about — the comp keeps
its id, the graph keeps every node — so nothing in the panel ever noticed, and
the sidecar stayed next to the old `.aep` where reopening the new one would
never find it.

The project's path now rides along on `NTL_ActiveComp()`, which the identity
watch already calls once a second. Carried there rather than in a second call
because that watch exists precisely to catch identity changes the revision gate
cannot see, and cheapness is its whole point.

`classifyProjectPath` (pure, in `src/reader.js`) names the four transitions:

| | meaning | what the panel does |
|---|---|---|
| `same` | nothing moved | nothing |
| `moved` | Save As | re-point the storage and save again at the new path |
| `saved` | an unsaved project was saved for the first time | enable storage and save |
| `unsaved` | the file went away | drop the storage, say so |

`graphFilePathFor` is the one place that path string is built, because two
places computing it is two places for it to drift, and a sidecar written where
nothing later reads it is a graph the user believes is saved.

Nothing is copied — the graph is already in memory, so re-pointing and saving is
the whole operation. Two deliberate refusals:

- **The old sidecar is left alone.** That `.aep` may still exist, and it still
  has its graph. A move is not a deletion.
- **A sidecar already at the new path, holding a different graph, is not
  overwritten.** It belongs to whatever was saved there before. The storage is
  still re-pointed, so `Save Graph` replaces it deliberately, but nothing is
  written automatically and the footer says why.

## 2 · Selecting a node now selects its layer

**Reported as:** selecting a node should act as selecting a layer, so effects
attached to it can be edited in the Effect Controls panel, or its properties in
the Properties panel.

After Effects' Effect Controls and Properties panels follow the layer
**selection** and nothing else. The panel never told AE anything about its own
selection, so a node carrying effects could be selected in the graph with no way
to reach those effects in the application that renders them.

`jsx/select.jsx` is a new host file, and new rather than folded into an existing
one because it fits neither contract: `reader.jsx` states that it writes nothing,
and `patch.jsx` states that it is the only file that writes to the project, in
one undo group per patch. Selection is neither:

- `layer.selected` is view state. After Effects neither marks the project
  modified nor puts it on the undo stack.
- it does not move `app.project.revision`, so P1.4's drift guard cannot see it —
  which is why the comp-switch watch exists at all, and which is exactly what
  makes this safe to send on every selection change.

An undo group here would be the bug: one entry out of S5's 99 spent on clicking
a node.

The rules, all tested against the real JSX in a VM:

- one selected node means one selected layer, and the others of ours are cleared;
- **a layer the graph does not own is never deselected by us.** The user did not
  ask the graph to manage it, so a selection the graph had no part in making is
  not the graph's to take away;
- a node with no layer behind it — an expression node, or a layer node whose
  layer the next patch has yet to create — selects nothing rather than clearing;
- an **effect node** resolves to its own host layer, the null the reconciler
  creates to carry it, because that is the layer whose Effect Controls holds the
  effect the user clicked;
- selection is **refused** when the active comp is not the one being reconciled:
  selecting inside a comp the user is not looking at changes what their next
  keystroke applies to;
- a node id reaches the host inside a string literal and is escaped the same way
  every other string in this project is. The test proves it by running the call
  and checking the project is still standing.

It is coalesced at 80 ms and skipped while a patch is in flight or a gesture is
open — arrowing through the outliner would otherwise be one round trip per
keystroke, behind a write it is never worth waiting for.

An **Effect Controls** button brings AE's own panel forward. It is a separate,
explicit action: Effect Controls follows the selection by itself once it is open,
and opening a panel is a decision about the user's workspace, not something to do
to them on a click.

## Still open

- No live AE acceptance. In particular, `layer.selected` is asserted here to be
  free of the undo stack and of `app.project.revision`; the fake models that,
  and AE has not confirmed it. If a selection does move the revision, the drift
  poll will see a spurious change once per click — annoying, not dangerous, and
  it would be fixed by adopting the revision after a selection.
- `Save a Copy` does not change `app.project.file`, so it produces no sidecar for
  the copy. Whether it should is a real question, not an oversight.
- Selection is one-way. An AE layer selected in the timeline does not select its
  node in the panel.
- The Effect Controls command id (2163) is taken as fixed with a name lookup as
  fallback, the same bet `NTL_ShowNewCompDialog` already makes.
