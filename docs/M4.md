# M4 — Durable Identity

**Status: IMPLEMENTED THROUGH M4.3; MANUAL AE VERIFICATION INCOMPLETE**

M4 wires the S3 comment-tag + native-ID identity scheme into production. The
implementation now captures native IDs after layer creation, targets a specific
layer when duplicate tags exist, strips the copied tag, re-binds a unique tag
whose native ID changed, and hydrates tagged layers when the panel opens.

This is not full persistence. Hydration recreates minimal layer nodes only; it
cannot recover canvas positions, standalone expression/effect nodes, effect
topology, or all graph-only relationships. More seriously, startup immediately
calls `touch()`, so the diff may clear graph-owned expressions and parent links
that hydration failed to reconstruct. Empty/unmanaged comps also receive the
three demo seed layers automatically. Reload must be made non-destructive before
this is used on valuable files. These issues remain open alongside M6, and the
three real-AE scenarios below have not been recorded as passing.

---

## Gaps this milestone addresses

Six gaps were discovered during the M3 review. Their current state is:

| # | gap | impact |
|---|---|---|
| 1 | Native ID lifecycle | Implemented in `graph.js`, `loop.js`, and patch receipts; dedicated receipt/binding tests are still owed. |
| 2 | Duplicate resolution | `ntlpLayer` can resolve by `nativeId`; the no-ID ambiguous case still refuses safely. |
| 3 | Clearing a copied tag | `setComment` exists and the diff emits it for duplicate copies; direct VM coverage is still owed. |
| 4 | Deleting a specific duplicate | `deleteLayer` carries and uses `nativeId`. |
| 5 | Precompose re-bind | Unique moved tags are classified `rebindable` and the loop updates the cached ID; the classifier is tested, the loop behavior is not. |
| 6 | Reload safety | Startup hydrates before starting the loop, but the immediate flush can still remove relationships absent from the hydrated graph; this remains unsafe. |

---

## Decisions

| question | decision | rationale |
|---|---|---|
| Duplicate handling | **Original keeps tag; copy is stripped** (`comment = ''`) and becomes unmanaged | The graph owns exactly one layer per node. A copy is the user's. |
| Precompose re-bind | **Accept the new nativeId** when the tag is intact and unique | The comment survived; only the handle changed. Update the cache, don't block. |
| Panel reload | **Hydrate from comp** — scan tagged layers and rebuild graph nodes, don't use `seedGraph()` | Prevents the deletion catastrophe. M6 (persistence) will add `.ntl` file loading. |
| Native ID in ops | **Ops carry `nativeId` alongside `node`** when disambiguation is needed | ExtendScript can resolve by `layer.id` when a tag scan is ambiguous. |
