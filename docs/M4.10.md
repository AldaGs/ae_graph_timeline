# M4.10 — an effect node is not a layer, and the outliner is Blender-shaped

**Status: IMPLEMENTED AND COVERED OFFLINE; LIVE AE ACCEPTANCE STILL OWED**

`npm test`: 199 passing. `npm run preflight`: six JSX targets clean. Panel
builds; the bundle grew 11 kB for the icon set, which is tree-shaken.

---

## 1 · An effect node had acquired a layer's transform — a regression

**Reported as:** when adding effect nodes (it adds as nulls by design) it should
not show the layer transform properties, only the effect name or display name.

This was M4.8's doing, and it was worse than a display problem.

An effect node's `props` are its effect **parameters**. The reconciler gives it a
host null to live on, and M4.8 taught `observeAfterPatch` to complete a freshly
created node from the layer After Effects actually made — which, for an effect
node, meant copying that null's `anchorPoint`, `position`, `scale`, `rotation`
and `opacity` straight into the parameter bag.

The display was the visible half. The other half: `diff` builds an effect node's
wanted effect as `params: node.props`, so those five transforms were sent to AE
as effect parameters, never matched anything, and the effect was **re-added on
every pass** — a patch per pass, forever, each one an undo entry. Reproduced:

```
effect node props after one patch:
  [ 'ADBE Gaussian Blur 2-0001', 'anchorPoint', 'position', 'scale', 'rotation', 'opacity' ]
next diff ops: [ 'addEffect' ]      ← and again, and again
```

The completion is now restricted to layer kinds. After the fix the node keeps
only its parameter and the graph converges to zero ops. Two tests hold it there:
one for effect nodes, one for expression nodes.

The inspector now also says what an effect node *is* — its display name and AE's
match name, read-only — and states plainly that the host null's transform belongs
to the machinery rather than to the node.

## 2 · The outliner reads like Blender's

**Reported as:** I want the outliner to look more like Blender does. You can
fetch icons from lucide that match After Effects layer types.

Blender's **look**, not its hierarchy. The first pass at this read the reference
screenshot as a specification for behaviour too and nested layers under their
parents; that was corrected on the same day, and the correction is the more
interesting half of the note.

**Every layer is a child of the composition and nothing else.** After Effects'
timeline is a flat stack, so nesting layers under their parents would make the
outliner disagree with the timeline about what the comp *is* — and it forced
"dragging a parent takes its children with it", which is a rule nobody asked
for. A layer's parent is a relationship, and the canvas is where a relationship
belongs. It survives here only as a tooltip, which costs no column and loses
nothing.

So a row's depth means one thing: a layer sits under its composition, and an
effect sits under the layer whose stack it is in. Three levels, and
`outlineRows` is written as a loop rather than a recursion because that is the
truth of the shape — a recursive walk would imply a depth the model does not
have.

The tree itself is data: `src/outline.js`, pure, with its own tests. The flat
order it prints is the AE stacking order, so what the user reads top to bottom
is what the comp holds, and `moveInOutline` is expressed over that order because
it is the whole of what AE is given.

What the tree contains:

| row | why |
|---|---|
| the **composition**, as a group | Blender's collection: chevron, icon, name, count, and the checkbox from the reference |
| **layers**, flat | the stacking order, top to bottom, parenting left to the canvas |
| **effects** under their layer | inline entries and flow-chained effect nodes alike. An effect is not a layer, has no position in the stack, and is never reordered |
| **Unwired effects**, as a group | an effect node just dropped on the canvas is wired to nothing, so no layer claims it — and it appeared *nowhere*. It sits here until it is wired, then moves under the layer whose stack it joined |
| **Expressions**, as a group | they are not layers and have no place in the stacking order; listing them among things that do would imply one |

Icons are lucide (`lucide-react`), one per AE layer kind, naming the same things
AE names: `Square` solid, `Axis3d` null, `Type` text, `PenTool` shape, `Image`
footage, `Clapperboard` comp and precomp, `Video` camera, `Lightbulb` light,
`Sparkles` effect, `Braces` expression. They are tinted in two tiers, the way
Blender separates an object from its data: layers neutral, effects green,
expressions blue.

The drawing details that actually make it read as that reference:

- a disclosure chevron per row with children, and a **reserved empty slot** on
  rows without any, so every icon in the tree lines up;
- **an indent guide per level**, not one per row. A single line at the content
  edge reads as a box rather than a tree the moment a row sits at depth 2;
- the group rows tinted and ruled, with the child rows inset;
- the label swatch and the visibility eye pinned right as one column — the comp
  row's checkbox sits in that same column so the right edge stays a column and
  not three;
- a hidden layer dimmed rather than removed: the row has to stay clickable, and
  its eye is how you get it back;
- a drop line above or below whichever half of the row the pointer is in.

The **checkbox on the composition row** is from the reference, and the honest
reading of it here is "is every layer in this comp visible". It is tri-state —
mixed when some are — and it wraps its writes in one gesture: S5 put AE's undo
stack at 99 entries, and hiding twelve layers is one thing the user did, not
twelve. It is the one place this component reaches past React, because
`indeterminate` cannot be set through an attribute.

Selection behaviour: an inline effect row selects the **layer** carrying it,
which is the layer whose Effect Controls holds it; a standalone effect node row
selects the node the user drew.

**The drag source is held in a ref, not in state.** React state set in
`dragstart` is not visible to the drop handler's closure until a re-render, and
a drag is a sequence of events rather than a render cycle. It happened to work
because real drags span many frames; the ref removes the dependency on that, and
is what made the behaviour verifiable at all.

### Smaller things that came with it

- The old `Outliner.css` styled against `--bg-canvas`, `--text-main` and three
  other variables that exist nowhere; `App.css` had a rule aliasing them onto the
  real `--ntl-*` names. Both are gone: the component uses the real names.
- The toolbar no longer wraps to two lines in a narrow panel. It scrolls its
  actions instead — a two-line toolbar eats the canvas and reflows as the user
  resizes.
- The browser fixture now carries a parent, an inline effect and an expression
  node, because those are shapes the outliner has to draw and a bare fixture
  would let them regress unnoticed in the one place they can be looked at
  without After Effects.

## Still open

- No live AE acceptance for either item.
- A layer's parent is only a tooltip here. If it deserves more, the place for it
  is a dim suffix on the row, not a nesting level.
- An effect node's parameter set is still whatever the graph happens to hold. AE
  is never asked for an effect's real parameter list, so `Tint` added from the
  menu has nothing to edit until something is wired into it. The inspector now
  says so instead of showing an empty panel, which is not the same as fixing it.
- Selection is still one-way: an AE layer selected in the timeline does not
  select its row here.

## Manual AE acceptance still owed

- [ ] Add an effect node → the inspector shows its name and match name and no
      transform; the graph settles after one patch instead of re-adding the
      effect on every pass.
- [ ] Parent one layer to another → the outliner does NOT move it, and says so
      on hover; dragging either row moves that row alone.
- [ ] The composition checkbox → every layer hides and shows, in one undo entry,
      and it reads mixed while only some are hidden.
- [ ] Add effects to a layer → they appear under it, and clicking one selects
      that layer in AE with its Effect Controls populated.
- [ ] Drag to reorder → one undo entry per drag, and the AE stacking order
      matches what the outliner reads top to bottom.
- [ ] Hide and show layers from the eye → AE follows, one undo entry each.
