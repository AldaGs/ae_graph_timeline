# M4.10 — an effect node is not a layer, and the outliner is a tree

**Status: IMPLEMENTED AND COVERED OFFLINE; LIVE AE ACCEPTANCE STILL OWED**

`npm test`: 199 passing. `npm run preflight`: six JSX targets clean. Panel
builds; the bundle grew 11 kB for the icon set, which is tree-shaken.

---

## 1 · An effect node had acquired a layer's transform — a regression

**Reported as:** when adding effect nodes (it adds as nulls by design) it should
not show the layer transform properties, only the effect name or display name.

This was M4.8's doing, and it was worse than a display problem.

An effect node's `props` are its effect **parameters**. The reconciler gives it a
host null to live on, and M4.8 taught `observeAfterPatch` to complete a freshly
created node from the layer After Effects actually made — which, for an effect
node, meant copying that null's `anchorPoint`, `position`, `scale`, `rotation`
and `opacity` straight into the parameter bag.

The display was the visible half. The other half: `diff` builds an effect node's
wanted effect as `params: node.props`, so those five transforms were sent to AE
as effect parameters, never matched anything, and the effect was **re-added on
every pass** — a patch per pass, forever, each one an undo entry. Reproduced:

```
effect node props after one patch:
  [ 'ADBE Gaussian Blur 2-0001', 'anchorPoint', 'position', 'scale', 'rotation', 'opacity' ]
next diff ops: [ 'addEffect' ]      ← and again, and again
```

The completion is now restricted to layer kinds. After the fix the node keeps
only its parameter and the graph converges to zero ops. Two tests hold it there:
one for effect nodes, one for expression nodes.

The inspector now also says what an effect node *is* — its display name and AE's
match name, read-only — and states plainly that the host null's transform belongs
to the machinery rather than to the node.

## 2 · The outliner reads like Blender's

**Reported as:** I want the outliner to look more like Blender does. You can
fetch icons from lucide that match After Effects layer types.

The old outliner was a flat list of layer rows. The new one is a tree, and the
tree is data: `src/outline.js`, pure, with its own tests.

**The thing that had to be decided first** is that Blender's outliner nests
objects under their parents, while After Effects' timeline is a flat stack in
which a layer's parent may sit anywhere. Both are true at once. The resolution:

- the tree **nests by parent**, because that is the relationship someone opens
  an outliner to see;
- the flat order is the tree's **depth-first walk**, so what the user reads top
  to bottom *is* the AE stacking order. Nothing is shown that does not
  correspond to a real position in the comp.

The consequence is deliberate: **dragging a parent takes its children with it.**
That is the only reading of "move this row" that keeps the two orders the same
thing, and `moveInOutline` is expressed over the flat order for the same reason —
the flat order is what AE is given, and the only thing a reorder can change.

What the tree contains:

| row | why |
|---|---|
| the **composition**, as a group | Blender's collection. Carries the layer count. |
| **layers**, nested by parent | the stacking order, top to bottom |
| **effects** under their layer | inline entries and flow-chained effect nodes alike, effects before children: an effect belongs *to* a layer, a child is a separate layer that merely points at it |
| **Unwired effects**, as a group | an effect node just dropped on the canvas is wired to nothing, so no layer claims it — and it appeared *nowhere*. It sits here until it is wired, then moves under the layer whose stack it joined. |
| **Expressions**, as a group | they are not layers and have no place in the stacking order; listing them among things that do would imply one |

Icons are lucide (`lucide-react`), one per AE layer kind, chosen to name the same
things AE names in its own timeline: `Square` solid, `Axis3d` null, `Type` text,
`PenTool` shape, `Image` footage, `Clapperboard` comp and precomp, `Video`
camera, `Lightbulb` light, `Sparkles` effect, `Braces` expression.

Behaviour, all verified in the browser preview:

- a disclosure chevron per row with children; collapse hides the subtree;
- an inline effect row selects the **layer** carrying it, which is the layer
  whose Effect Controls holds it; a standalone effect node row selects the node
  the user drew;
- the label swatch and the visibility eye are pinned right, as in the reference;
- a hidden layer is dimmed, not removed — the row has to stay clickable, and its
  eye is how you get it back;
- a drop line shows above or below whichever half of the row the pointer is in;
- a move that would change nothing, or that cannot be made (a row dropped inside
  its own subtree), sends no reorder — it would cost an undo entry for a drag
  that moved nothing.

Two robustness notes, both tested: a layer whose parent is gone is shown at the
top level rather than dropped, and a parent cycle — which the graph refuses to
build, but a hand-edited `.ntl` file is not the graph's to vouch for — does not
hang the panel.

**The drag source is held in a ref, not in state.** React state set in
`dragstart` is not visible to the drop handler's closure until a re-render, and a
drag is a sequence of events rather than a render cycle. It happened to work
because real drags span many frames; the ref removes the dependency on that, and
is what made the behaviour verifiable at all.

### Smaller things that came with it

- The old `Outliner.css` styled against `--bg-canvas`, `--text-main` and three
  other variables that exist nowhere; `App.css` had a rule aliasing them onto the
  real `--ntl-*` names. Both are gone: the component uses the real names.
- The toolbar no longer wraps to two lines in a narrow panel. It scrolls its
  actions instead — a two-line toolbar eats the canvas and reflows as the user
  resizes.
- The browser fixture now carries a parent, an inline effect and an expression
  node, because those are shapes the outliner has to draw and a flat fixture
  would let the tree regress unnoticed in the one place it can be looked at
  without After Effects.

## Still open

- No live AE acceptance for either item.
- Reordering reassigns `order` from the tree walk, so dragging a parent moves its
  children in the comp too. This is coherent and documented, but it is a choice:
  AE itself lets a child sit anywhere relative to its parent. If that turns out
  to matter, the fix is to nest for display only and reorder among siblings.
- An effect node's parameter set is still whatever the graph happens to hold. AE
  is never asked for an effect's real parameter list, so `Tint` added from the
  menu has nothing to edit until something is wired into it. The inspector now
  says so instead of showing an empty panel, which is not the same as fixing it.
- The comp group row has no toggle of its own. A "hide every managed layer"
  control would be one gesture and one undo entry, but it is a feature nobody
  asked for yet.
- Selection is still one-way: an AE layer selected in the timeline does not
  select its row here.

## Manual AE acceptance still owed

- [ ] Add an effect node → the inspector shows its name and match name and no
      transform; the graph settles after one patch instead of re-adding the
      effect on every pass.
- [ ] Parent one layer to another → the outliner nests it, and dragging the
      parent moves the pair in the AE timeline.
- [ ] Add effects to a layer → they appear under it, and clicking one selects
      that layer in AE with its Effect Controls populated.
- [ ] Drag to reorder → one undo entry per drag, and the AE stacking order
      matches what the outliner reads top to bottom.
- [ ] Hide and show layers from the eye → AE follows, one undo entry each.
