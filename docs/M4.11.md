# M4.11 — Blender's inspector, After Effects' numbers

**Status: IMPLEMENTED AND COVERED OFFLINE; LIVE AE ACCEPTANCE STILL OWED**

**Reported as:** match the inspector UI, draggable editable values like After
Effects', not just type on edit.

`npm test`: 215 passing. `npm run preflight`: six JSX targets clean. Panel
builds.

---

## What was wrong

In After Effects every number is a **scrubber**: drag across it and the value
follows the pointer, click it and you type. That is not a nicety, it is how the
application is used — and the inspector had one comma-separated text box per
property, so `position` was the string `"960, 540"`, every adjustment was a
select-all-and-retype, and nothing could be dragged at all.

A single box for a vector is also a text field pretending to be two numbers.
There was no way to nudge Y without rewriting X.

## What it is now

Blender's layout, because the outliner beside it already is one — and After
Effects' behaviour inside each field.

```
SOLID  [ Card                    ]

▾ Transform
      Position X  [      960  px ]
               Y  [      540  px ]
         Scale X  [      100   % ]
               Y  [      100   % ]
        Rotation  [        0   ° ]
         Opacity  [      100   % ]
▾ Compositing
           Blend  [ normal     ▾ ]
▾ Fill
  ADBE Fill-…  R  [        1     ]
               G  [      0.5     ]
▸ Add effect
```

The layout, taken from the reference:

- **Collapsible sections** under a chevron — the same lucide chevron the
  outliner uses, so the two panels speak one language.
- **One component per row**, stacked. Not side by side: a vector laid out
  horizontally reads as a sentence, and Blender stacks for a reason.
- **A right-aligned label column**, in which only the first row of a vector
  carries the property's name and the rest carry just their axis. That economy
  is what keeps a four-channel colour from repeating its matchName four times
  down a 244px panel.
- **The unit inside the field**, right after the number — `0 px`, `1.000` — not
  in a column of its own outside it.
- **Flat inset fields** with no border until focused, and **step arrows that
  appear on hover** at each end. The arrows are the discoverable half of the
  affordance: a user who has not worked out that a field can be dragged can
  still click one.
- **A narrow state column** on the right, where Blender puts its lock and
  animate dot. Ours says one thing: an input driven by an expression edge is not
  the user's to type into, because the expression *is* the value there.
- The node's **kind and name in a strip at the top**, above the panels.

The behaviour, taken from After Effects:

- **Drag** to scrub. **Shift** is coarse (×10), **Ctrl/Cmd** is fine (×0.1) —
  AE's convention, deliberately *not* Blender's, where Shift is the fine one.
  The layout is Blender's because it is being looked at; the modifiers are AE's
  because this panel is docked in AE and that is the muscle memory in the hands.
- **Click** to type. Enter commits, Escape reverts, and anything that is not a
  number puts the old value back without an error — typing over a field wrong is
  something a user does constantly and by accident.
- **Arrow keys** step by one, or ten with Shift, or a tenth with Ctrl. While the
  field is open for typing they step the *draft*, so the number that gets sent
  is the number on screen.

## Where the work went

**The arithmetic is pure and tested** — `src/scrub.js`, which knows nothing
about React. The feel of a drag can then be checked without a pointer, and three
of the four things worth getting right are arithmetic:

- **A drag is measured from where it started, not frame to frame.** Accumulating
  per-frame deltas drifts, and the drift is exactly what a user notices when
  they waggle the pointer. A drag that returns to where it began returns the
  value with it — there is a test for precisely that.
- **Float dust never reaches the graph**, because the graph's values become a
  comp's values. A colour channel scrubbed from 0.07 gives 0.08, not
  0.08000000000000002.
- **Precision is not truncated in the name of removing dust.** AE reads
  669.33332824707 out of a comp; scrubbing that by one gives 670.33332824707.
  The first version of `tidy` rounded to the step and silently threw away eight
  decimals of a value the user had not touched — caught by a test written from
  a real figure in `test/persistence.test.js`.
- **Only known limits clamp.** Opacity is 0–100 because that is a fact. An
  effect parameter's range is something AE never tells us, and a clamp on a
  guess is a value the user cannot type their way out of.

The unit table covers the five transform properties. Anything else is an effect
parameter, whose units AE does not hand over, so the step is a **heuristic that
only picks a step**: a four-component vector sitting inside 0..1 is a colour and
scrubs at 0.01; a lone small number scrubs at 0.01; everything else at 1. Being
wrong costs a drag that feels coarse or fine, and the number can still be typed.

**A scrub is one gesture**, so a drag across a field costs one undo entry in
After Effects however many frames it spans — the same rule P1.5 applies to a
drag on the canvas, for the same measured reason (S5: the stack holds 99). The
gesture opens only once the press is definitely a drag, because a click that
opened one would spend an entry on nothing.

**Pointer capture**, so a scrub survives leaving the field. At 20px of row
height a drag that stopped at the field's edge would be unusable.

## Two bugs the verification found

Driving the field in the browser rather than reasoning about it caught both:

- **Enter depended on blur.** It called `blur()` and let the blur handler
  commit, which works only if the field was focused in the first place. Enter
  now commits directly.
- **Arrow keys stepped the graph value while the draft masked the result.** The
  value changed underneath a number that never moved on screen. Arrows now step
  whatever the user is actually looking at.

## Inline effect parameters are editable at last

`Card` has a Fill effect; its colour lives in `node.effects[i].params`, not in
`node.props`, so it was the one place left where the inspector printed a number
nothing could touch — the canvas showed it and no editor existed for it. The
model already supported the write (`setEffectParam`, and the diff's `setEffect`
op); what was missing was a command and a place to put it. The inspector now has
an effect block per inline effect, which is the panel's Effect Controls.

`setEffectParam` gained the validation `setNodeProperty` already had — finite
numbers, matching vector length, a parameter that exists. In the model rather
than at the panel, because the model is what the writer is handed and the panel
is not the only thing that can reach it.

## One exposure closed on the way

`beginGesture` throws on a closed loop, and closing one is an ordinary event: the
comp changed, or After Effects is quitting. A scrub in progress across that
moment would have thrown from a pointer handler. Both gesture calls in
`graphCommands` now refuse rather than throw — the graph is still the graph, and
the panel is still usable without a loop behind it.

## Smaller things

- The inspector's rows are `.ntl-irow`, not `.ntl-row`: the canvas nodes
  already own that class, and the three-column grid imposed on those would have
  broken every node on screen.
- A long label used to eat its own axis letter — one string put the ellipsis
  through the `R` of a colour's first channel. Name and axis are separate spans
  now, and the name is the half that gives way: an axis with no name is still
  readable, a name with no axis is not.
- Property names are capitalised as AE capitalises them — `anchorPoint` reads
  "Anchor Point". An effect parameter keeps its matchName, because its display
  name is something AE never hands over and a prettied-up guess would be worse
  than the truth.
- Fields do not stretch. A lone opacity field spanning the panel reads as a text
  box again, which is the one thing these are not.

## Still open

- No live AE acceptance. In particular the *feel* — one unit per pixel — has
  only been judged against a browser preview. It is one constant in
  `src/scrub.js` if it turns out to be wrong under a pen or a trackpad.
- AE hides the cursor during a scrub and lets the value run past the screen
  edge. This does not: it uses pointer capture, so a long drag still ends at the
  edge of the display. Pointer lock would fix it and is worth trying in a real
  CEP panel before being trusted.
- No colour swatch. A Fill's colour is four numbers, which is honest but is not
  what AE shows; a real picker needs AE's own dialog, which is a host call.
- An effect parameter's units, display name and range are all still guesses,
  because the reader never asks AE for an effect's parameter definitions. That
  is the one change that would retire every heuristic in this note.
- The React Flow `nodeTypes` warning in the console is a StrictMode
  double-render artifact, not the bug `Canvas.jsx`'s header is about — that
  object is module-level and its identity is stable.

## Manual AE acceptance still owed

- [x] Drag a Position field → the field previews smoothly while dragging, the
      final value reaches the comp on release, and the whole drag is **one**
      undo entry. CEP cannot safely hold one AE undo group open across
      asynchronous `evalScript` calls, so host writes are release-committed.
- [x] Drag with Shift, then with Ctrl → ten times coarser, ten times finer.
- [x] Click a field, type a number, press Enter → it lands; press Escape

- [x] Type nonsense and commit → the old value returns and no error appears.
- [x] Arrow a field up and down, with and without Shift.
- [x] Scrub an inline effect's parameter → AE's Effect Controls shows the same
