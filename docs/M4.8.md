# M4.8 — the four reported defects, and R1/R2 from the M4.7 review

**Status: FIXED IN CODE AND COVERED OFFLINE; LIVE AE ACCEPTANCE STILL OWED**

Four defects were reported from live use of the M4.7 build, and two of the three
open findings in `M4.7_REVIEW.md` turned out to be the same story told from the
other end. They are fixed together because they share one theme: the panel was
treating "After Effects is not exactly what the graph expects" as an emergency,
in four different places.

`npm test`: 171 passing. `npm run preflight`: five JSX targets clean. Panel
builds. No live AE acceptance — the manual scenarios below are still owed.

---

## 1 · A timeline edit demanded reconciliation and froze the panel

**Reported as:** changing a layer property in the timeline pops up the message
that it needs reconciliation.

`src/drift.js` has always classified changes into blocking and non-blocking, and
`BLOCKING` deliberately excludes `propChanged`: the design says the graph is the
source of truth and the next diff simply corrects a value the user nudged. But
`usePanelLifecycle` answered EVERY `drift` event by calling `setDrift(...)`, and
`canEdit` is `… && !drift`. So a single nudge in the timeline put up "choose
which version should become the source of truth" and disabled the toolbar, the
outliner, the canvas and the inspector until the user answered — which is also
the whole of report 3 below.

The rule is now in one pure, tested place, `classifyDrift` in
`src/reconcile.js`:

| condition | verdict |
|---|---|
| the report carries a **blocking** change | `decide` — an identity the graph held is gone; nothing can be adopted through that |
| the graph is **dirty** (changes not yet written) | `decide` — two intentions collided, and only the user can rank them |
| anything else | `adopt` — the comp as the user left it becomes the graph |

Adoption runs through the existing `captureCompState`, which refuses rather than
half-adopts: if anything in the comp cannot be represented, a pending write would
be left behind, so it falls back to `decide`. The panel says
"Adopted N changes from After Effects" and stays editable.

## 2 · A reconstructed comp produced a different node from a created one

**Reported as:** reconstructing a comp makes a different node in params; the
nodes need all transformation properties from creation.

The reader reads five transform properties (`anchorPoint`, `position`, `scale`,
`rotation`, `opacity`), so `hydrateFromComp` rebuilt a node with five. But the
panel's `layerProps` seeded a created node with three (`position`, `scale`,
`opacity`), or two for a null. The same layer was therefore a different node
depending on how the panel came to know about it — and it is not cosmetic: the
inspector renders one editor per entry in `props`, and `setNodeProperty` throws
`Unknown property` for one the node does not already carry. A created layer's
anchor point and rotation were unreachable until the panel was reopened.

- `TRANSFORM_PROPS`, `transformPropsFor(kind)` and `defaultLayerProps(kind, {width, height})`
  now live in `src/graph.js`, next to the reader's property table they mirror.
- `anchorPoint` is deliberately **not** seeded. Its default belongs to the
  layer's source, not the comp — `[50,50]` for a null, `[0,0]` for text, the
  centre for a full-frame solid — so a guess would be written into AE and move
  the layer. `observeAfterPatch` in `src/loop.js` now completes a freshly
  created node from the layer AE actually made, which is both the right shape
  and the right value.
- The comp's real `width`/`height` are carried through the reader, so a new
  layer is centred in *this* comp instead of in a hardcoded 1920×1080 one.

## 3 · Node properties were not editable

Three separate causes, all now addressed:

- the permanent `drift` freeze from report 1 (the dominant one);
- a created node missing the properties from report 2;
- **effect node parameters had no editor anywhere.** The canvas renders them as
  text and the inspector's property block was gated on `layer`, i.e. "not an
  effect and not an expression". They are editable now. An effect node with no
  parameters in the graph says so rather than rendering an empty panel.

The remaining cases where the inspector is intentionally read-only are the
startup states (`empty`, `needs-decision`, `no-comp`, `comp-changed`) and
blocking drift. Those are decisions, not defects.

## 4 · "Cannot run a script while a modal dialog is waiting for response" on quit

**Reported as:** on closing After Effects, always "Unable to execute script at
line 0."

After Effects refuses to run any script while a modal dialog is waiting — its own
"Save changes?" on quit included — and it announces the refusal with an alert of
its own. The panel polls twice a second from two independent intervals, so every
quit produced a stream of those alerts. Nothing in the panel knew the host was
going away.

There is no API for "is a modal open", so the gate is driven from the two things
that can be known, and both stop the calls at the source — the only place they
can be stopped:

- **CEP's quit event.** `panel/public/CSInterface.js` gained the
  `addEventListener` / `removeEventListener` / `dispatchEvent` pass-throughs the
  vendored shim never had, and the bridge listens for
  `com.adobe.csxs.events.ApplicationBeforeQuit`. A quit suspends the transport
  permanently; `resume()` cannot undo it. `beforeunload` does the same for the
  panel closing.
- **A reply the host never ran.** The bridge sees every reply, so it is where
  `EvalScript error.` and an empty reply are noticed; one closes the gate for
  five seconds. A dialog the user is actually reading now costs one complaint
  instead of one per poll.

A modal call the *panel* asked for (AE's own New Composition dialog) is a third
state: `beginModal()`/`endModal()` stop the pollers via `host.busy` while
leaving the transport open for the dialog call itself.

## R1 · Label and blend mode disappeared at the reader boundary

`jsx/reader.jsx` built layer records without either field, and `src/diff.js` only
emits those writes for fields it observed — so the inspector could change a blend
mode, the diff would report clean, and AE kept the old value forever.

- The blend-name ↔ `BlendingMode` table moved to `jsx/common.jsx`, beside the
  property table, for the reason that table is there: the reader turns an integer
  into a name and the writer turns a name into an integer, and a second copy
  would let them disagree — which reads as drift, not as a bug.
- Both fields are read only for **managed** layers, the same rule the properties
  follow: a field on a layer that is not ours must not reach the diff.
- A mode this build cannot name comes back `undefined` with a warning, never
  guessed as `normal`, or the diff would try to "correct" it on every pass.
- Camera and light layers have no blending mode and asking throws, so that is a
  predicate rather than a counted read error.
- `label` joined `drift.js`'s layer facts and `projectSnapshot` learned
  `setLabel` and `setEnabled`.

Fixing this made `test/fake-ae.js` visibly wrong: it defaulted every layer to
label 0 while `addNode` defaults a solid to 1, so an agreeing graph produced a
dirty first pass. The fake now defaults to the graph's own `KIND_DEFAULT_LABEL`.

## R2 · Duplicate cleanup left stale tag counts inside the patch

`ntlpSetComment` changed the host comment without touching the patch context's
tag index, so a later op on the surviving original still saw two claimants and
failed **after** the cleanup had landed.

`ntlpReindexTag` recounts a tag against the comp, and both `setComment` (in both
directions, because a rollback re-tags) and `deleteLayer` now use it — a delete
reindexes rather than wiping, since removing one of a duplicated pair leaves the
tag still claimed.

Writing the test for the re-tag direction exposed a second, worse bug:
`ntlpLayer` ignored an explicitly supplied `nativeId` whenever the tag happened
to be unique, resolving by tag instead. That is the corruption the native id
exists to prevent — a delete aimed at a copy could remove the original — so an
op that names an id is now honoured unconditionally, and an id that is not in
the comp is refused. `setComment` got its own resolver, since it is the one op
whose target need not already carry the tag.

## Still open

- **R3 stands.** Nothing here was verified in live After Effects. The four
  manual scenarios below are the acceptance gate, and the quit fix in particular
  can only be proven there: the offline test drives a fake CEP, not AE's own
  modal.
- `com.adobe.csxs.events.ApplicationBeforeQuit` is assumed to fire in AEFT. If it
  does not, the unusable-reply backoff still reduces the alerts from a stream to
  roughly one per five seconds, but it does not eliminate them. Confirm which
  path actually carries the quit.
- An effect node's parameter set is whatever the graph happens to hold. AE is
  never asked for an effect's real parameter list, so `addEffectNode('ADBE Tint',
  …, {})` still produces a node with nothing to edit.
- Adoption clears the panel's undo/redo history, as `useAeChanges` always did.
  A timeline nudge therefore costs the panel's own history. Worth revisiting.
- M4's Phase D items and M4.6's workflows are untouched by this pass.
