# M4.6 — footage in, expressions with a real editor

**Status: IN PROGRESS — Slice A Project-panel footage drop implemented offline;
live CEP drag acceptance and the remaining slices are open**

M4.6 closes the gap between a graph that demonstrates the reconciler and a
graph that can assemble a small real shot. Before M7, Node Timeline must be
able to bring source media into the composition and expression nodes must be
comfortable enough for more than a one-line experiment.

This phase has two primary delivery slices:

1. **Project footage and layer adoption** — drag an existing AE Project item
   into the graph as a managed layer node, or deliberately adopt an existing
   unmanaged comp layer without duplicating either asset or layer.
2. **Monaco expression editing** — replace the expression node's textarea with
   one full editor surface for the selected expression, while preserving the
   graph's one-gesture/one-AE-write contract.

The other open M4.6 items — the installed-effect catalogue and keyboard
connection authoring — remain in the milestone, but they are not silently
folded into these two slices.

## Decisions locked by this document

### “Add Project footage” and “adopt this layer” are different commands

They share a word but not a transaction:

| command | source | result |
|---|---|---|
| **Drop Project footage** | one or more items already imported in AE's Project panel | the graph creates one managed layer/node per existing `FootageItem`; no project item is imported or copied |
| **Import** on an unmanaged layer | a layer already in the active comp | that exact native layer receives a graph tag and becomes a node; no project item or layer is copied |
| **Ignore** on an unmanaged layer | a layer already in the active comp | no AE write; the graph remembers not to keep offering that native layer |

The first command instantiates existing media as layers. The second changes
ownership of layers already in the comp. Neither command imports a file into
the AE project; Project-panel import, interpretation, sequence detection,
folders, proxies, and relinking remain native After Effects workflows.

### A footage node owns a layer, not the media file

AE owns footage interpretation, relinking, proxies, alpha interpretation,
colour management, and project-bin organization. Node Timeline stores enough
source identity to recreate its layer, but it does not become an asset manager.

The graph adds this source record to a footage node:

```js
source: {
  kind: 'footage',
  itemId: 137,                 // cached AE project-item identity
  path: 'D:/shot/plate.mov',   // recovery hint, not the primary live handle
  importAs: 'footage'
}
```

`itemId` is the live identity used to create the layer. `path` is diagnostic
and is updated when AE reports that footage has been relinked. It is never used
to import, recreate, or deduplicate a project item: AE may intentionally hold
multiple interpretations of one file, and an image sequence cannot be safely
reconstructed from the first frame's path alone.

The schema remains version 1 only if the new field is optional and old readers
preserve it losslessly. If validation or meaning changes incompatibly, bump the
schema rather than guessing during reopen.

### The drop is explicit and comp-scoped

The drop mutates only the active composition. It runs from an explicit native
drag from AE's Project panel, is guarded by the inspected `compId`, serialized
through the existing host lane, and grouped into one clearly named undo entry.
Selecting a Project item temporarily makes it `app.project.activeItem`; that is
an "away" state, not evidence that the bound composition was closed. On drop,
the host snapshots `app.project.selection`, resolves footage by item ID, and
restores the bound composition before the guarded patch runs.

Opening the panel, selecting or dragging Project items without dropping, scanning
unmanaged layers, and choosing Ignore all perform zero AE writes.

### Monaco is one editor, not one editor per node

Expression cards remain cheap graph summaries. Selecting or double-clicking an
expression opens a resizable editor in the inspector/editor area. There is at
most one mounted Monaco editor instance, backed by one model per expression
node.

Putting Monaco inside every React Flow card would multiply DOM, models,
listeners, and worker traffic with graph size. It would also make canvas zoom
and pan responsible for code-editor layout. The graph card instead shows the
name and a short read-only code preview; the dedicated surface owns editing.

### AE expression JavaScript is not browser JavaScript

Monaco provides editing, JavaScript tokenization, search, brackets, indentation,
and completion. It does **not** decide whether an expression is valid in After
Effects.

The first implementation disables TypeScript semantic diagnostics that would
incorrectly reject AE globals such as `value`, `time`, `thisComp`, and
`thisLayer`. A small versioned declaration/completion catalogue describes the
AE globals Node Timeline supports. AE remains the authority: after a commit,
the reader reports the property's `expressionError` and the panel shows it
beside the editor without deleting or rewriting the user's code.

Node Timeline never evaluates expression text in the panel.

## Slice A — Drag Project footage into the graph

### User flow

1. The user imports and organizes media with AE's Project panel, including its
   native PNG-sequence import options.
2. The user drags one or more selected footage items from the Project panel and
   drops them at a position on the graph canvas.
3. CEP treats the browser drop only as intent; it does not trust browser file
   paths. The host reads the current `app.project.selection`, keeps footage
   items, reports unsupported selections, and restores the graph's bound comp.
4. The panel creates pending footage nodes containing the returned item IDs and
   starts one graph gesture for the whole drop.
5. The diff emits source-backed create operations. The host verifies the same
   active `compId`, resolves every existing project item by ID, calls
   `comp.layers.add(footageItem)`, tags each layer, and returns layer IDs.
6. The receipt binds `node.nativeId` and confirms `node.source.itemId`. The ordinary
   post-patch read learns duration, dimensions, transform defaults, and AE's
   canonical current source path.
7. Failure removes the pending graph nodes or rolls the transaction back. It
   never deletes, imports, or duplicates a user-owned Project item.

### First-release scope

- Still images, image sequences, video, and audio already represented by AE as
  `FootageItem` project items.
- Multiple selected footage items become one graph gesture and one patch.
- Layered Photoshop/Illustrator comps, folders, projects, solids, generated
  media, and composition items are rejected by this first drop slice.
- A footage layer can participate in ordering, parenting, blend mode, effects,
  expressions, visibility, labels, drift, undo/redo recognition, and
  persistence exactly like other layer nodes.

### Read model

For a managed source-backed layer, `jsx/reader.jsx` adds a source record:

```js
source: {
  kind: 'footage',
  itemId: layer.source.id,
  name: layer.source.name,
  path: layer.source.mainSource.file.fsName,
  missing: layer.source.footageMissing === true
}
```

Every capability is guarded. Generated footage and exotic sources may have no
file; an unreadable field is omitted and counted under the reader's existing
partial-read policy. Unmanaged layers still receive only the safe summary used
by the import chooser until the user explicitly asks to adopt one.

### Diff and patch behavior

- `createLayer` gains an optional `source` descriptor. A footage create without
  a resolvable source is refused; it must never fall through to `addSolid()`.
- Resolution is by project item ID only. No file import, path lookup, or display
  name lookup is permitted.
- A receipt returns `createdIds[nodeId]` and
  `createdSourceIds[nodeId]`.
- Deleting a footage node deletes its managed layer, as today. It does **not**
  remove the project item: other AE layers may use it, and layer ownership does
  not imply asset ownership.
- Missing footage is visible on the node and in the inspector. Relink remains
  an AE Project-panel action; Node Timeline never silently reimports it.
- A clean second diff is mandatory.

### Files expected to change

| layer | responsibility |
|---|---|
| `src/graph.js` | validate and preserve `node.source`; bind the returned project-item ID |
| `jsx/reader.jsx`, `src/reader.js` | read and normalize source identity, path, and missing state |
| `src/diff.js` | plan source-backed creation and compare source identity without name guesses |
| `jsx/patch.jsx`, `src/patch.js` | resolve an existing item ID, add its footage layer, return IDs, and roll back partial layer creation |
| `src/drift.js`, `src/reconcile.js` | classify source replacement and capture safe relinks without converting footage into a solid |
| `src/persistence.js` | retain the optional source descriptor and reject malformed source records |
| `panel/src/graphCommands.js` | expose one transactional multi-item Project drop command |
| panel lifecycle/UI | receive canvas drops, query AE selection, position nodes, and show rejected-item errors |
| fake AE and tests | model Project selection, temporary non-comp activity, item identity, and `comp.layers.add(item)` |

## Slice B — Import or Ignore existing unmanaged layers

### Discovery

The startup reader continues to treat untagged layers as user-owned and
unwritable. The panel displays an unobtrusive count and opens a chooser listing
native ID, name, kind, index, and source summary. Reading this list does not
authorize a full property read or a write.

### Import transaction

Importing an existing layer is not implemented by merely adding a node to the
graph. That would make the normal diff see a missing managed layer and create a
duplicate. Instead:

1. Re-read the chosen native layer under the current comp/revision guard.
2. Build a candidate node from the full observed facts.
3. Reserve a unique node ID and name.
4. Apply a targeted `setComment`/adoption operation to that exact native ID.
5. Publish the candidate graph only when the host receipt succeeds.
6. Re-read and require an empty diff.

If the layer moved, disappeared, became tagged, or changed comps between steps,
the action is refused and nothing is adopted by guesswork.

An adopted footage layer receives the same `source` descriptor as footage
created through a Project-item drop. Shapes, text, nulls, solids, precomps, cameras,
and lights retain their observed kind and only the properties the reader can
represent safely.

### Ignore behavior

Ignore is graph-only state:

```js
ignoredLayers: [501, 509]
```

- Ignore hides those native IDs from the current graph's unmanaged-layer
  prompt and persists in the `.ntl` sidecar.
- Ignore all records the current unmanaged set; later unmanaged layers still
  appear.
- Removing a layer from AE makes its ignored ID harmless; stale IDs may be
  pruned on save.
- Ignore never tags, selects, disables, moves, or otherwise writes the layer.

## Slice C — Monaco expression editor

### Packaging and CEP feasibility gate

Add `monaco-editor` as an exact, tested panel dependency and use its supported
ESM surface. Do not add a React wrapper unless it solves a demonstrated problem;
the direct API makes model and disposal ownership explicit.

The panel is Vite-built but the installed CEP extension loads from a local URL.
Monaco normally relies on web workers, and local-file worker behavior differs
across browsers and CEP's embedded Chromium. Therefore the first implementation
step is a disposable installed-panel spike:

1. Bundle only the editor and JavaScript/TypeScript worker with Vite.
2. Provide `MonacoEnvironment.getWorker` before importing the editor.
3. Prefer an inline/blob worker build so it does not depend on a worker fetched
   from a `file://` path; update the extension CSP only as narrowly as required.
4. Verify cursor movement, input, completion, search, resize, theme, and worker
   startup in the supported AE/CEP version.
5. Record bundle size and cold-open time.

If CEP rejects workers, M4.6 still ships Monaco's core editing and JavaScript
tokenization with worker-backed diagnostics/completion disabled. It must not
silently fall back to running heavy language services on the UI thread. The
current textarea remains a development fallback until the installed-panel gate
passes.

### Editor lifecycle

- Lazy-load Monaco the first time an expression is opened; it is not part of
  the initial graph canvas chunk.
- Use a stable model URI such as
  `inmemory://node-timeline/<graphId>/expressions/<nodeId>.js`.
- Keep a model while its expression node exists so selection changes preserve
  undo history and cursor state.
- Dispose editor listeners, the editor instance, completions, and every model
  when the graph closes; dispose one model when its node is deleted.
- Observe the panel with `ResizeObserver` and call `editor.layout()` without
  causing a graph redraw.
- Map Node Timeline theme tokens into a Monaco light/dark theme rather than
  styling Monaco internals ad hoc.

### Editing contract

| action | result |
|---|---|
| type | updates Monaco's model and a local draft; no AE round trip |
| `Ctrl/Cmd+Enter` | commits the draft through `commands.setExpression` |
| blur to another node/panel | commits once if the draft changed |
| `Escape` | restores the last committed graph text and keeps AE unchanged |
| graph undo/redo or AE history adoption | replaces the editor model without creating a new user edit |
| delete expression node | disposes its model and removes connected expression edges through the existing command path |

A focus session is one graph gesture. However many Monaco change events occur,
the host receives at most one patch and AE receives one undo entry when the
session commits. Autosave may persist drafts on its existing debounce, but a
draft is never presented as already applied to AE.

The ownership header (`// ntl:edge:<id>`) is generated by the graph-to-expression
compiler and is not shown as editable text. Monaco edits only
`expressionNode.expression`.

### Language assistance

First release:

- JavaScript syntax colouring, bracket matching, folding, find/replace,
  multi-cursor editing, indentation, and editor-local undo/redo.
- Completions and hover text for a small reviewed AE surface: `value`, `time`,
  `thisComp`, `thisLayer`, `transform`, `effect`, `wiggle`, and the property
  value types Node Timeline exposes.
- Snippets for common expressions, inserted as text and never executed.
- AE runtime errors displayed after a host read with node/property context.

Not in M4.6:

- A full After Effects type definition, language server, expression debugger,
  profiler, formatter that rewrites user code, or evaluation in the panel.
- Claiming modern JavaScript syntax is valid merely because Monaco accepts it.
- Editing hand-written, untagged AE expressions. Node Timeline continues to
  refuse ownership of expressions it did not author.

### Files expected to change

| layer | responsibility |
|---|---|
| `panel/package.json`, lockfile | exact Monaco dependency |
| panel Monaco bootstrap | lazy ESM import, worker setup, features/language registration, theme |
| expression editor component | editor/model lifecycle, resize, keyboard commands, accessibility and fallback |
| `ExpressionNode.jsx` | lightweight preview and open-editor action |
| inspector/layout | resizable editor surface and runtime error display |
| `graphCommands.js` | one explicit commit boundary; no write per Monaco change event |
| `jsx/reader.jsx`, `src/reader.js` | carry `expressionError` only when AE reports it |
| tests | editor lifecycle with a stub adapter plus installed CEP acceptance |

## Safety and failure rules

1. Every host mutation is guarded by the active comp ID and current project
   revision.
2. A drag cancelled outside the graph changes neither graph nor AE; unsupported
   Project items are rejected without creating layers.
3. An import failure cannot leave a graph node claiming a layer that does not
   exist.
4. Adoption addresses an unmanaged layer by native ID and rechecks that it is
   still untagged immediately before writing.
5. No command writes to an ignored layer.
6. A footage project item is never imported, copied, or deleted by graph-layer
   creation, deletion, failure, or rollback.
7. Monaco never evaluates code and never edits the generated ownership tag.
8. Monaco loading or worker failure cannot make existing graphs unreadable;
   the plain editor fallback remains usable and reports the reduced capability.
9. Expression runtime errors are data, not patch failures. The user's text is
   retained and the error is visible.
10. Every successful import or expression commit settles to an empty diff.

## Automated coverage

### Footage and adoption

- A drag cancelled outside the graph produces no command, node, host call, or save.
- A supported selected Project item creates no new `FootageItem`; it creates one
  tagged layer, one node, one undo entry, and a clean second diff.
- Unsupported selections and missing item IDs are refused without orphan layers/items.
- A multi-selection creates one node/layer per footage item in one graph gesture.
- Selecting Project footage keeps the existing comp binding alive until drop.
- Layer and source IDs from the receipt bind to the graph and survive save/reopen.
- Existing project items resolve by ID even when renamed.
- Relinking updates the recovery path without changing node identity.
- Deleting a footage node leaves a shared project item intact.
- Importing an unmanaged layer tags that exact native layer and creates no
  second layer.
- A stale/disappeared/already-tagged adoption target is refused atomically.
- Ignore and Ignore all perform no AE writes and persist only their chosen IDs.

### Monaco

- Monaco is lazy-loaded once and only one editor instance is mounted.
- Models use stable unique URIs and are disposed on node/graph deletion.
- Typing causes no host calls; commit causes one graph command and one patch.
- Escape restores the committed text; blur and `Ctrl/Cmd+Enter` commit once.
- Switching nodes never writes the previous expression twice.
- External graph restore updates the model without echoing a command.
- Generated ownership tags never enter the editable model.
- AE expression errors appear without replacing the user's text.
- Worker failure selects the declared fallback and does not freeze startup.

## M4.6 completion gate

These two slices are complete when:

1. a first-time user can import media with AE's native Project workflow and drag
   the resulting footage item—including an image sequence—onto the graph without
   duplicating or reinterpreting the asset;
2. an existing unmanaged layer can be imported or ignored explicitly, with
   zero accidental duplication or mutation;
3. a multi-line expression can be authored in Monaco, committed once, undone,
   reopened, and diagnosed from AE;
4. all automated coverage, JSX preflight, panel tests, and production build pass;
5. the installed CEP acceptance matrix above passes and failures remain in the
   result record;
6. the full installed-effect catalogue and keyboard connection authoring are
   either completed or explicitly carried forward before M4.6 is closed.

M7 does not start merely because these features compile. The M4.13 scale gate,
the remaining M4.6 completion items, and this live matrix must all be closed.
