# M4.12 — one reading of the modifiers, and text layers that hold text

**Status: IMPLEMENTED AND COVERED OFFLINE; LIVE AE ACCEPTANCE STILL OWED**

`npm test`: 228 passing. `npm run preflight`: six JSX targets clean. Panel
builds.

---

## 1 · The modifiers are read once

**Reported as:** make the modifiers consistent with AE everywhere.

They were not. A value can be moved three ways — dragged, arrowed, or stepped
with the field's own arrows — and each read the event for itself. The step
arrows honoured Shift and silently dropped Ctrl, so the same key meant "finer"
in two places and nothing in the third.

The fix is not to patch the arrow but to remove the possibility. `scrubModifiers`
is now the only thing in the project that looks at an event's modifier state,
and the three paths hand it the event that caused them. Ctrl **or** Cmd, because
AE's fine modifier is the platform's command key and honouring one would be
wrong on half the machines this runs on. Both held at once is coarse: a user
pressing everything is more plausibly reaching for the big movement.

The test that matters is the last of the three: given the same modifiers, a drag
and an arrow key have to land on the same number, or the field behaves
differently depending on which part of it the user touched.

## 2 · Text layers hold text

**Asked as:** let's make text layers editable. Or is it on a different part of
the roadmap?

Not on the roadmap — and that turned out to be the interesting part of the
answer. `patch.jsx` created text layers with `addText('')` and **nothing** in
the reader, the model, the diff, the writer or the panel ever touched the
string. So "+ Text" made an empty layer that could never be filled. That is not
a missing feature, it is a half-built one, which is worse: the button implies a
capability that does not exist.

It is now a property like any other, following the same rules the others follow:

| layer | what it does |
|---|---|
| `jsx/common.jsx` | `ntlrTextProp` — one place that finds Source Text, so the reader and the writer cannot look in different places |
| `jsx/reader.jsx` | reads the string for text layers only, and reports `textLocked` when AE has it keyframed or expression-driven |
| `src/reader.js` | carries both, **only when observed** |
| `src/graph.js` | `node.text`, written through `setNodeField`, refused for a layer with nowhere to put one |
| `src/diff.js` | emits `setText`, and carries the string on `createLayer` |
| `jsx/patch.jsx` | `ntlpSetText` |
| panel | a Text section in the inspector, and the string on the canvas card |

Four decisions worth stating:

**The writer mutates the TextDocument it was handed.** Constructing a fresh one
would be shorter and would silently reset the layer's font, size, colour,
tracking and justification to AE's defaults — the user's typography thrown away
to change a word. There is a test that sets Futura 120 and checks it survives.

**The string travels with the creation**, on the `createLayer` op, rather than
following as a `setText` in the next pass. A layer that had to wait would be
empty for one write cycle, which is a frame of the comp showing the wrong thing.
Letting `addText` build the document is safe *there* and only there: a layer that
did not exist a moment ago has no typography to preserve.

**A keyframed or expression-driven string is reported by the reader, not
discovered by the writer.** Both throw in After Effects, and the panel can only
show the field read-only if it is told beforehand. The diff then does not ask,
and the writer refuses anyway if something else does.

**Everything is gated on the reader having observed it.** `undefined` means "not
read", and the diff refuses to write a field it never saw — which is what stops
a solid from being "corrected" to a string.

### The bug hiding underneath

`test/fake-ae.js` declared `class TextLayer {}` and three siblings as empty
classes, so every `layer instanceof TextLayer` in `reader.jsx` was false and the
fake could only ever answer `'footage'`. The comment said this was deliberate —
and for solids it is right, since a solid *is* a footage layer in AE — but it
meant the text branch could never run in a test, and camera, light and shape
layers had never been exercised either. They now answer from the layer's own
`kind` through `Symbol.hasInstance`.

Also found: `parseCompState` has never carried `nodeId`. Not a bug — the diff
derives identity from `comment` through `nodeIdFromTag`, which is the tag being
the identity — but it is worth knowing before writing a test that looks for one.

### And one more Escape-commits-anyway bug

The inspector's text editor commits on blur, and Escape blurred. `setDraft` in
the Escape handler had not applied by the time the blur handler read the draft,
so a cancelled edit was committed regardless — the same shape as the Enter bug
in `ScrubValue` last time. A ref is visible immediately, which is the whole
reason it is one. Caught by driving the field in the browser, not by reading it.

**Enter is deliberately not a commit.** After Effects text is multi-line, and a
field where Enter ends the edit cannot hold a second line. Blur commits, Escape
cancels.

## Still open

- No live AE acceptance for either item.
- Only the string. Font, size, colour, tracking, justification and per-character
  styling are read and written by nobody — the TextDocument is preserved
  wholesale, which is the right default but is not the same as supporting them.
- Text animators, path options and per-character 3D are untouched and out of
  scope for the MVP.
- The reader asks for Source Text on every text layer on every read. For a comp
  full of titles that is a cost nobody has measured.
- A locked (keyframed) Source Text renders read-only with a lock icon, and that
  path has not been seen on screen — the browser fixture cannot produce one, and
  it needs a real keyframed text layer.

## Manual AE acceptance still owed

- [ ] "+ Text", then type in the inspector → the words appear in the comp.
- [ ] Style a text layer in AE (font, size, colour), then change the string from
      the panel → the styling survives.
- [ ] Type a two-line string → both lines reach the comp, and the card shows two.
- [ ] Keyframe Source Text in AE → the field goes read-only with a lock, the
      panel does not fight it, and no drift is reported.
- [ ] Edit the string in AE → the panel adopts it rather than writing over it.
- [ ] Reopen the panel on a comp with text layers → the strings come back.
- [ ] A whole text edit is one undo entry.
- [ ] Step arrows with Ctrl held → a tenth of a step, matching a Ctrl-drag.
